# M3.2 - Receive automation

M3.2 adds the receive-side primitives that make RexxTelnet useful as an ARexx automation client.

## Commands

- `PEEK` returns currently buffered application data without consuming it.
- `READ` returns currently buffered application data and consumes the returned bytes.
- `WAITFOR text [timeout]` waits for text in the decoded Telnet application stream.
- Quoted first arguments are supported, for example `WAITFOR "login prompt:" 10`.

`WAITFOR` uses seconds for the optional timeout. The default is 10 seconds and the supported range is 0-3600 seconds.

## Semantics

The automation buffer receives bytes after Telnet framing and option negotiation have been removed, but before ANSI/VT terminal interpretation. This keeps matching independent from screen rendering while preserving the actual application stream.

The receive buffer is bounded to 4096 bytes. On overflow the oldest bytes are discarded so recent prompts remain available.

A successful `WAITFOR` consumes buffered data through the end of the matched text. Its ARexx result is `MATCH` with RC 0. Timeout returns `TIMEOUT` with RC 5. A disconnected or failed session returns `WAIT FAILED` with RC 10.

`PEEK` is non-destructive. `READ` consumes only the bytes returned in `RESULT`; because ARexx command results are currently capped at 255 bytes plus terminator, repeated `READ` calls can drain larger buffered input safely.

## Runtime

While `WAITFOR` is active, the Amiga runtime continues pumping the TCP session and terminal output. This allows prompts to arrive and remain visible while an ARexx script is blocked waiting for them.

## Tests

Host tests cover:

- receive buffer append, search, peek, read and consume-through behavior;
- quoted `WAITFOR` parsing;
- `WAITFOR`, `READ` and `PEEK` dispatch;
- preservation of multi-word `SENDLINE` payloads;
- case-insensitive `GET`/`SET` property names.

Native Amiga/Bebbo compilation and RexxMast runtime qualification remain separate qualification work.
