# M4.1 — Transport hardening

M4.1 hardens the TCP/Telnet session lifecycle before native qualification.

## Delivered

- `rt_transport_send_all()` loops until the complete buffer has been written or an error occurs.
- Application data, Telnet negotiation replies and NAWS subnegotiation now use send-all semantics.
- Socket EOF and receive/send errors close the transport and reset Telnet negotiation state.
- Reconnect starts from a closed transport, empty receive buffer and fresh Telnet parser/state.
- Duplicate supported `WILL`/`DO` negotiations are acknowledged only on the first state transition.
- Duplicate `DO NAWS` no longer emits repeated `WILL NAWS` or repeated NAWS payloads.
- POSIX transport no longer relies on C99 `snprintf()`/`getaddrinfo()` and is compiled under the strict C89 host flags.
- Amiga `bsdsocket.library` lifecycle is closed on disconnect and connection failure.

## Host qualification

`make check` now includes:

- partial-write coverage for `rt_transport_send_all()`;
- duplicate Telnet negotiation suppression;
- EOF -> disconnected/reset state;
- reconnect from a clean protocol state;
- strict-C89 compilation of `transport_posix.c`.

## Remaining qualification

The Amiga backend still requires a Bebbo GCC native build and runtime qualification with a real `bsdsocket.library` stack. M4.1 does not claim native runtime PASS.
