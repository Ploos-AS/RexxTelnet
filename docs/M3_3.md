# M3.3 — Capture and binary automation

M3.3 completes the first broad ARexx automation surface for RexxTelnet.

## Added commands

### `SENDHEX bytes`

Sends application bytes expressed as hexadecimal. The bytes still pass through the Telnet outbound encoder, so a literal `FF` is correctly escaped on the Telnet wire.

Accepted examples:

```text
SENDHEX 00 FF 1B 41
SENDHEX 00ff1b41
SENDHEX 0x00:0xFF:0x1B:0x41
```

Malformed or empty hex input returns RC 10 with `SYNTAX`.

### `CAPTURE file`

Starts capture to an AmigaDOS path. Capture records the decoded Telnet application stream before terminal rendering. Telnet negotiation bytes are therefore excluded, while ANSI/application escape bytes are preserved.

Starting capture while another capture is active fails with RC 10 and `CAPTURE FAILED`.

### `CAPTURE STOP`

Stops the active capture. If capture is not active, the command returns RC 5 and `CAPTURE NOT ACTIVE`.

## GET properties

The following properties are available in addition to `COLUMNS` and `ROWS`:

- `CONNECTED` — `1` or `0`
- `LOCAL_BINARY` — local Telnet BINARY state
- `REMOTE_BINARY` — remote Telnet BINARY state
- `REMOTE_ECHO` — remote ECHO state
- `LOCAL_SGA` — local SUPPRESS-GO-AHEAD state
- `REMOTE_SGA` — remote SUPPRESS-GO-AHEAD state
- `LOCAL_NAWS` — local NAWS state
- `RXBYTES` — bytes currently buffered for READ/PEEK/WAITFOR
- `CAPTURE` — `ON` or `OFF`
- `CAPTUREFILE` — most recently selected capture path
- `CAPTUREERROR` — `1` after a capture write failure, otherwise `0`

Property names are case-insensitive.

## Data-path contract

Incoming data follows this order:

1. socket bytes
2. Telnet decoding/negotiation removal
3. decoded application-stream observer (capture)
4. READ/PEEK/WAITFOR receive buffer
5. ANSI/VT terminal parser and display

This keeps automation independent from terminal rendering and prevents Telnet control negotiation from entering capture files.

## Tests

Host-side tests now cover:

- spaced and compact `SENDHEX`
- capture start/stop dispatch
- session property dispatch
- decoded application observer
- escaped inbound IAC becoming one captured/application byte

Native Amiga capture, RexxMsg result handling and filesystem behavior remain part of M5 runtime qualification.
