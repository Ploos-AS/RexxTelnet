# M2.2 — Amiga event loop

## Goal

Make the interactive client usable without blocking either the network or the Amiga console.

## Delivered

- non-blocking socket readiness API
- POSIX `select()` readiness backend
- Amiga `WaitSelect()` readiness backend
- `CON:` input readiness through `WaitForChar()`
- interactive Amiga runtime loop
- decoded Telnet output routed through the terminal parser and then to `CON:`
- terminal input routed through Telnet IAC escaping to the socket
- CSI controls reconstructed for the Amiga console backend
- local Ctrl-] escape terminates the interactive session
- command line form: `RexxTelnet host [port]`, default port 23

## Event-loop model

The runtime polls two readiness sources:

1. TCP socket readability;
2. Amiga console input readiness.

Only a ready source is read. If neither source is ready, the task yields with a one-tick `Delay()` instead of spinning.

This structure is intentional: M3 can add the ARexx port as another event source without changing the Telnet protocol or terminal layers.

## Remaining qualification

M2.2 is implemented but not yet native-runtime-qualified. Qualification still needs:

- Bebbo GCC `-m68000` build
- visible FS-UAE run
- real connection to a Telnet/BBS endpoint
- keyboard input verification
- ANSI/CSI visual verification
- NAWS verification on the wire
- clean remote disconnect and reconnect tests

These checks belong before declaring the interactive runtime release-ready.
