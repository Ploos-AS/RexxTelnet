# M4.2 — Session and automation hardening

M4.2 tightens automation behaviour before native qualification.

## Receive-buffer overflow policy

The automation receive buffer remains bounded at 4096 bytes. When incoming decoded application data would exceed the capacity, RexxTelnet keeps the newest bytes and drops the oldest bytes. The cumulative number of discarded bytes is tracked for the current connection.

New properties:

- `GET RXBYTES` — bytes currently buffered
- `GET RXDROPPED` — cumulative bytes discarded because the receive buffer overflowed
- `GET RXCAPACITY` — configured receive-buffer capacity (4096)

The overflow counter resets on a new connection together with the receive buffer.

## WAITFOR cancellation

`WAITFOR text [timeout]` can now be cancelled locally with Ctrl-C on AmigaOS.

Results:

- match: RC 0, `RESULT=MATCH`
- timeout: RC 5, `RESULT=TIMEOUT`
- Ctrl-C cancellation: RC 5, `RESULT=CANCELLED`
- disconnect or receive/display failure: RC 10, `RESULT=WAIT FAILED`

The normal interactive event loop also observes Ctrl-C and exits cleanly.

## Capture recovery

Capture write failures remain fail-closed: the capture file is closed, capture changes to `OFF`, and `GET CAPTUREERROR` becomes `1`. Starting a new capture file is the recovery operation and clears the capture-error flag after the new file opens successfully.

`GET CAPTUREFILE` retains the last selected path for diagnostics even if capture stops or fails.

## Host qualification

Host tests cover:

- bounded receive-buffer overflow
- exact dropped-byte accounting
- newest-data retention
- WAITFOR cancellation result mapping

Native Bebbo/AmigaOS qualification is still required for Ctrl-C signalling and capture I/O behaviour.
