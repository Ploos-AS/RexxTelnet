# M4.3 — Terminal and ANSI hardening

M4.3 preserves terminal control sequences that the earlier terminal parser could lose or reconstruct incorrectly.

## Changes

- CSI private prefix `?` is preserved, so sequences such as `ESC[?25l` and `ESC[?25h` survive parsing and reconstruction.
- Non-CSI two-byte escape sequences such as `ESC 7` and `ESC 8` are forwarded instead of discarded.
- The terminal control callback now carries an explicit prefix:
  - `RT_TERM_PREFIX_NONE` for normal CSI
  - `RT_TERM_PREFIX_PRIVATE_QMARK` for private CSI
  - `RT_TERM_PREFIX_ESC` for non-CSI ESC sequences
- Amiga console reconstruction emits the original control form.
- Ctrl-] remains the local escape key, but bytes preceding Ctrl-] in the same console read are sent before the client exits instead of being discarded.

## Host tests

`tests/test_terminal.c` covers:

- fragmented normal CSI
- private CSI (`ESC[?25l`)
- non-CSI ESC (`ESC 7`)
- NAWS generation and IAC escaping

The app-session test callback was updated to the hardened terminal control interface.

## Remaining terminal limitations

This is still an ANSI/VT100-ish baseline, not a complete terminal emulator. M5 qualification must verify representative BBS ANSI screens visibly in FS-UAE and identify any sequences that Amiga `CON:` does not render as expected.

## Qualification status

M4.3 is implemented and host-testable. Native Bebbo `-m68000` compilation and visible FS-UAE runtime qualification remain part of M5.
