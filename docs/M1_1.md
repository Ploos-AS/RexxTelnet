# M1.1 — Session integration and hardening

M1.1 joins the transport, Telnet parser and option policy behind one session I/O API.

## Delivered

- `rt_session_io` owns protocol and transport state
- connect resets Telnet state before a fresh session
- disconnect closes transport and resets negotiated state
- outbound application data is Telnet-IAC escaped
- receive pump decodes Telnet framing before exposing application data
- negotiation events automatically generate policy replies
- fragmented IAC and negotiation sequences are tested across feed boundaries

## Invariants

The parser state is preserved between receives, so a TCP packet boundary is never treated as a Telnet message boundary.

A reconnect starts with no negotiated BINARY, ECHO or SGA state inherited from the previous connection.

Application consumers see decoded Telnet payload bytes, not negotiation commands.

## Deferred

The current `rt_session_io_send()` scratch buffer limits one call to 256 payload bytes. This is acceptable for the current terminal/ARexx command path and can later be replaced by chunked streaming without changing the public contract.

Socket readiness/event-loop integration belongs to M2 when the Amiga terminal loop is introduced.
