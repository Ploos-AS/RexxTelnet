# M2.1 — Terminal/session integration

## Goal

Join the M1 Telnet/session core and M2 terminal core into one reusable interactive session layer before adding ARexx.

## Delivered

- `rt_app_session` owns transport, Telnet negotiation state and terminal state
- keyboard/application bytes are Telnet-escaped before transport send
- received TCP bytes pass through the Telnet parser before reaching the terminal parser
- Telnet negotiation replies are sent automatically
- NAWS is an explicit local Telnet capability
- `DO NAWS` is answered with `WILL NAWS`
- the current terminal dimensions are sent immediately after NAWS becomes active
- disconnect resets negotiated Telnet state
- host integration tests use a fake transport to verify the full byte path

## Data paths

Transmit:

`keyboard -> rt_app_session_send_input -> IAC escaping -> transport`

Receive:

`transport -> Telnet parser -> negotiation handling / decoded data -> terminal parser -> terminal output`

## NAWS

The initial terminal dimensions are provided when `rt_app_session_init()` is called. When the peer sends `IAC DO NAWS`, RexxTelnet responds with `IAC WILL NAWS` and then sends an RFC 1073 NAWS subnegotiation containing those dimensions.

A later resize API can reuse the same NAWS builder without changing the session architecture.

## Tests

`tests/test_app_session.c` verifies:

- decoded Telnet data reaches the terminal output callback
- `DO NAWS` produces `WILL NAWS` plus an 80x24 NAWS payload
- keyboard data containing IAC is doubled before transmission

## Remaining before interactive Amiga runtime qualification

The reusable session core is now connected, but the Amiga application event loop still needs non-blocking/multiplexed console and socket I/O. That should be completed before claiming a real interactive Amiga runtime PASS.
